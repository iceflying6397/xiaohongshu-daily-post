Agent 和 LLM，到底啥关系？🤖

总听到这两个词？可以先把 LLM 想成“大脑”，把 Agent 想成“有工具、能办事的助手”。🧠🛠️

这里说的是基于 LLM 的 Agent，不是所有类型的智能体。

01｜一个是模型，一个是系统 🧩
LLM 是大语言模型，负责理解输入、生成内容，也能帮助判断下一步该做什么。
Agent 是围绕模型搭起来的系统：给它目标，接上工具，再让它根据执行结果继续调整。
所以，Agent 通常会用到 LLM，但 LLM 本身不等于完整的 Agent。

02｜关键在“做完再看” 🔄
常见过程是：理解目标 → 决定下一步 → 调用工具 → 观察结果，再决定继续还是停止。
模型提出调用请求，真正读文件、查资料等动作由外部程序执行。
只接一个工具，不一定就算 Agent；如果步骤完全写死，通常更接近工作流。

03｜用整理资料举个例 📂
示意场景：你想把三份资料整理成摘要文档。
LLM 可以读懂提供给它的内容、生成摘要。
Agent 则可以在工具和权限允许时，读取文件、生成摘要、写入文档；发现漏读，还能继续补齐。
📌 能做哪些事，取决于实际工具与权限；能行动，也可能判断出错，结果仍要核对。

💡 记住：LLM 提供语言与判断能力，Agent 把这些能力组织成围绕目标的行动。
